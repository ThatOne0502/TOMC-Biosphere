# TOMC-Biosphere

> 📘 **数据驱动教程** — [data-driven.zh-CN.md](data-driven.zh-CN.md)

一个世界之所以有生机，不在于里面站着多少生物，而在于这些生物彼此之间有没有关系。

原版 Minecraft 有生物，却没有关系。鸡可以永远站在蠹虫旁边。花可以长在同一个位置直到被人打掉。末地石自末地生成以来就没变过样子。**TOMC-Biosphere** 想做的就是把这缺失的另一半补上——用数据补，而不是写死在代码里。

## 它做了什么

四套系统，全部由你可以直接编辑的文件驱动，不需要写 Java。

### 🍖 食物链关系

生物构成真实的食物网。捕食者猎杀，猎物逃跑——而且这包括了那些本来完全不战斗的被动生物。

| 捕食者 | 猎物 |
| --- | --- |
| 鸡 | 蠹虫 |
| 犰狳 | 蜘蛛 |
| 豹猫 | 苦力怕 |
| 海豚 | 鱿鱼 |
| 北极熊 | 鱼（`#minecraft:fishes`） |
| 亡灵（`#biosphere:hostile_undead`） | 牲畜 |
| 骷髅射手（`#biosphere:skeleton_archers`） | `#biosphere:passive_prey` |
| 幻翼 | 末影螨 |
| 潜影贝 | 末影螨 |
| 恼鬼 | 悦灵 |

而反方向共有二十个主语：

悦灵逃恼鬼 · 牲畜逃亡灵 · 鱼逃北极熊 · 鱿鱼逃海豚 · 村民逃骷髅 · 苦力怕逃豹猫 · 末影螨逃离所有猎杀它的生物 · 蠹虫逃鸡 · 蜘蛛逃犰狳。

本身没有近战攻击的生物——鸡、犰狳、豹猫——会获得一套新的近战 AI。伤害、追击速度与攻击冷却都可配置，因为「一只会杀人的鸡」是一个设计选择，而不是自然规律。

### 🥕 进食互动

动物会啃食周围的世界，各自带绵羊式低头动画，所以这件事你是能看见的，而不是只能靠猜。

- **牛**吃草，也会吃菌丝，并按可配置概率转化为**哞菇**。
- **哞菇**啃食蘑菇，并把菌丝变回泥土——正好是牛的逆过程。
- **猪**寻找成熟的作物、西瓜与南瓜。
- **骆驼**寻路到仙人掌并从根部开始吃，于是一根仙人掌柱会被从下往上吃掉。
- **马、驴、骡**像绵羊一样吃草。

### 🌱 随机刻演替

三十条规则跑在随机刻上——正是原版草蔓延所用的机制。没有轮询，没有排程；方块在世界决定 tick 它的时候才变化。

- 花朵凋谢并掉落对应的染料：全部十六种染料花，外加四种双层花（向日葵、丁香、玫瑰丛、牡丹）。
- 矮草长高，或者枯死；在向日葵平原上会演替成更高的形态；在繁花森林里会让位给花朵。
- 枯草演替成活植株；枯叶堆把它下方的草方块变成**灰化土**。
- 末地石在露天下长出紫颂花；紫颂植株又会枯萎。
- 绯红与扭曲菌岩蔓延植被；下界植物凋零。

每条规则都可以携带**谓词**（`biomes`、`can_see_sky`、`block` 等），所以一条规则可以窄到「只在末地高地、只在能看见天空的地方」。

### 🧊 末影人搬运白名单

末影人会捡起 `minecraft:enderman_holdable` 里的东西——一份人工维护的、约二十个方块的清单，多年未变，而且任何数据包都无法扩充它，只能整个替换掉那个标签。

本模组让你改用**整个创造模式物品栏分类**来重建这份清单：

- 勾选十一个内容分类的任意组合，白名单就是所有被勾选分类里的全部方块——只勾「自然方块」一个分类就是 243 个方块，如果你要的就是这个效果。
- 一份手写的**黑名单**会在之后被扣除，并且永远优先：`biosphere:enderman_holdable_blacklist` 覆盖末地石、基岩、黑曜石与哭泣的黑曜石、返回传送门框架与折跃门，以及三个管理员分类里的全部方块（命令方块三种、拼图方块、结构方块、结构空位、屏障、光源方块）。无论其它分类勾了什么，这些方块都永远不会被搬走。
- 多方块结构——床、门、双层植物——会被过滤掉，所以末影人不会只搬走一半结构、把另一半悬在空中。
- 关掉覆写，就完全回到原版标签。没有任何东西被就地改写。

### 🐚 自然刷新

两种生物获得了新家：**幻翼**游荡于末地小岛（`small_end_islands`、`end_barrens`），**末影螨**爬行于末地中部与高地。

## 设计思路

1. **一切皆数据。** 上面每一种行为都是 `data/biosphere/` 下的一个 JSON 文件，从数据包资源管理器读取。往数据包里加一个文件，行为就存在；删掉它，行为就消失。原版文件从不被替换。
2. **默认值即可用，无需配置。** 模组自带一套完整、可玩的规则。它的设计目标是装完就能忘掉它。
3. **服务端是权威。** 配置存放在服务端，并在玩家加入时下发给客户端。客户端永远不可能和它所处的世界产生分歧。
4. **只有软依赖。** 除 Fabric API 外没有任何硬依赖。Creefern 与 Cloth Config 是被检测的，不是被要求的。
5. **规则各自失败、失败得响亮。** 一个格式错误的规则文件会加载失败并在日志里给出原因，且不会连带拖垮其它任何东西。

## 环境要求

- Minecraft **1.21.11**
- Fabric Loader **0.19.5+**
- [Fabric API](https://modrinth.com/mod/fabric-api) —— 必需
- [Cloth Config](https://modrinth.com/mod/cloth-config) —— 配置界面所需
- [Mod Menu](https://modrinth.com/mod/modmenu) —— 可选；用于从模组列表打开配置界面

## 配置

服务端权威，在游戏内通过 **Mod Menu → TOMC-Biosphere** 编辑：

| 分类 | 内容 |
| --- | --- |
| **功能模块** | 食物链 AI、环境演替、生物刷新数据包的开关；牛→哞菇转化概率。 |
| **被动生物攻击** | 获得新近战 AI 的生物的伤害、追击速度、攻击冷却与逃跑速度。 |
| **末影人搬运** | 搬运白名单覆写开关，以及白名单由哪些创造模式分类构成。 |
| **creefern 联动** | 与 Creefern 模组的兼容设置，含自动检测。 |

白名单是在**服务端**展开的：末影人第一次询问某个方块时惰性展开，配置每次保存时重新展开——所以在游戏内改分类不需要重启。专用服务器上直接改文件则需重启后生效。

由于配置是服务端权威的，这个界面只在世界真正运行的地方可编辑：单人游戏里，或者你还没加入任何世界时。作为客人连在别人的服务器上时，所有条目都会置灰、保存也没有任何效果——这正是设计意图。

## 兼容性与边界

- 🧩 除 Fabric API 外全部可选。缺 Cloth Config 意味着界面不存在，模组照常运行。
- 🌍 环境演替系统会动态给源方块加上 `isRandomlyTicking`。它改变的是方块何时被 tick，而不是世界能否加载——但一套非常复杂的规则集会消耗 tick 时间。
- 🥚 食物链 AI 通过**给生物追加 goal** 实现，而不是替换生物。另一个重写了同一套 goal 选择器的模组可能与之冲突。
- 🔁 `AiCapabilities.MELEE_CAPABLE` 中的生物本就有近战攻击，它们只获得新的目标选择，**被动生物攻击**里的数值对它们不生效。
- 👀 末影人覆写只拦截原版 goal 里那一处 `is(BlockTags.ENDERMAN_HOLDABLE)` 判定。它不改变末影人想拿什么，只改变它们被允许拿什么。
- 🧪 OptiFine 与着色器：**未测试**，不给出任何结论。

## 给整合包作者

- 所有内容都走 Fabric 正常注册流程。没有任何 mixin 替换原版文件，也没有任何原版 JSON 被覆盖。
- 三套数据系统可以从 **功能模块** 分类里整套关掉，如果你只想要模组的一部分。
- 食物链规则是叠加式且带命名空间的——整合包可以和我们自己的规则并存，放在它自己的 `data/<包名>/biosphere_food_chain/` 下。
- 末影人白名单提供了公开的 Java 入口（`BiosphereApi`），供其它模组注册自定义多方块过滤器，这样一个新增了两段式方块的模组可以阻止末影人只搬走其中一半。

## 从源码构建

```bash
./gradlew build          # Windows: gradlew.bat build
./gradlew runClient      # 开发用客户端
./gradlew runServer      # 开发用服务端
```

需要 Java 21。首次构建会下载 Minecraft、映射与依赖，因此需要几分钟；之后的构建只需几秒。

产物位于 `build/libs/`，形如 `tomc-biosphere-<版本>.<构建次数>-fabric+mc1.21.11.jar`。每次构建成功后构建次数自增，且该目录会被清理，只保留最新一代产物。
